# H1-3: tell the owner when a payment fails (event type and copy)

**From:** H1 (Stripe webhook, billing state, audit writer) **To:** C0 (event contract, `packages/shared/src/events.ts` and `contracts/events/events.schema.json`), then C6 (notifications) **Status:** open, not blocking

## What
`actionForStripeEvent('invoice.payment_failed')` returns `notify_owner` with template `billing_payment_failed`, but there is no event type the owner notification path can carry. EVENT_TYPES is a closed list and the dispatcher only renders types it knows, so H1 cannot send this notice without a contract change. H1 already has the seam: `WebhookDeps.notifyOwner(tenantId, template, eventId)`, called best effort after the billing state is recorded. In production it is currently not wired, so a failed payment is recorded (billing status `past_due`, audit entry with `ownerNotice`) but the owner is not messaged by us. Stripe's own failed-payment email still goes out if enabled in the Stripe dashboard, and when retries run out the tenant is suspended and the existing `tenant.state_changed` notice fires.

## Proposed change
1. C0: add event type `billing.payment_failed` to `EVENT_TYPES` and the schema, data `{ attemptCount?: integer, nextAttemptAt?: string (ISO) }`. No Stripe free text, no amounts. Always scoped to one tenant like every other event.
2. C6: render it in `templates.ts`, route it to `['telegram', 'email']` in `routing.ts`, and add it to the detail-type list in `notifications-stack.ts`.
3. H1 (follow-up, one line): wire `notifyOwner` in `createWebhookDeps` to emit it with `correlationId` = the Stripe event id.

## Suggested copy (checked against `@1145/conversation-style`, chat channel, no issues)
- Body: `Your latest payment didn't go through, and your front desk is still answering calls. We'll try the card again over the next few days. If it keeps failing, calls will pause, so it's worth updating your card soon.`
- Subject and push title: `Payment didn't go through`

Also worth a look in C6: today `tenant.state_changed` to `suspended` says only "Your front desk is paused." When `data.reasonCode` is `billing` the owner needs the reason, for example:
`Your front desk is paused because the last payment didn't go through. It starts answering again as soon as a payment goes through.`
(This one also passes the style check.) H1 sends `reasonCode: 'billing'` and `actor: 'billing'` on both the suspend and the resume.
