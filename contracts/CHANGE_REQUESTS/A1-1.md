# A1-1: runtime session id length, runtime and memory infra

**From:** A1 (agents) · **To:** C1 (router, `services/channels`) and the infra owner (`infra/cdk`)

## 1. Router: pad the runtime session id (C1)
`InvokeAgentRuntime` requires `runtimeSessionId` of at least 33 characters. `routeInbound` builds `onb-<onboardingId>`
(`onb-` plus a 26-character ULID is 30) and `admin-<tid>-<channel>-<user>` (can be short for a Telegram id). Short ids
are rejected by AgentCore.

Proposed: keep the format but pad deterministically in the AgentCore invoke step in `router-deps.ts`, for example
`sessionId.padEnd(33, '0')` or append a fixed suffix like `-1145-session-v1`. It must stay stable per owner so memory
continues. The agents derive the onboarding memory key from `payload.onboardingId` (not the padded id), and use the
padded runtime session id as the admin memory key, so either choice works as long as it is deterministic.

## 2. Infra: SSM parameters, memory, runtime role (infra owner)
A1 ships scripts (`agents/deploy/`) and does not deploy. The router needs, per stage:
- SSM `/1145/<stage>/agentcore/onboarding-arn` and `/admin-arn` (A1 script writes them after the owner deploys).
- `bedrock-agentcore:InvokeAgentRuntime` on both ARNs for the router role (`channels-stack.ts` TODO(C1)).
- Optionally manage the two memories and the runtime execution role in CDK instead of the script. IAM list is in
  `agents/deploy/README.md`.
