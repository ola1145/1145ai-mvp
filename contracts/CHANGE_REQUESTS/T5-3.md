# T5-3: the call token's `st` claim, its 20 minute lifetime, and the 403 it leads to (SEC-08)

**From:** T5 (resolvers), with T0 (the check). **Needs:** C0 (`packages/shared/src/tokens.ts`, `contracts/openapi/tenant-tools.yaml`).

## What changed (T5 and T0 files)
- `/internal/resolve/number` and `/internal/resolve/widget` now mint the call token with a lifetime of 20 minutes (was 60). The worker ends every call and chat at 15 minutes and never refreshes a token.
- The token carries `st`, the same state the worker is told in the response body: `active`, `over_cap` or `suspended` (the stricter of the route item and `PROFILE.state`; an unrecognised route state counts as `suspended`).
- `tenant-auth.ts` (T0): for a `customer-agent` token, `st` other than `active` makes `createBooking`, `rescheduleBooking`, `cancelBooking` and `requestHandoff` answer 403 `tenant_not_active` with a line that offers to take a message. Reads, `takeMessage`, and tokens with no `st` (router and bench tokens) are unaffected. An `st` value that is not one of the three is treated as `suspended`.

## 1. `packages/shared/src/tokens.ts` (C0)
`TenantTokenClaims` has no `st`, so the resolver mints with a wider local type and the verifier reads it with a cast. Please add:
```ts
st?: TenantRuntimeState;   // 'active' | 'suspended' | 'over_cap': route state when the token was minted (resolvers only)
```
and let `verifyTenantToken` reject a token whose `st` is present and not one of those three. Related to SEC-07 (per-issuer keys and claim validation): the resolver is the only issuer that should ever set `st`.

## 2. `contracts/openapi/tenant-tools.yaml` (C0), additive only
- `ResolvedCall.token`: describe the lifetime (20 minutes) and that it is call-scoped.
- `createBooking`, `rescheduleBooking`, `cancelBooking`, `requestHandoff`: add `403` code `tenant_not_active`. Example `sayToCaller`: "I can't do that from here right now, but I can take a message for the team."

## 3. Voice worker and chat worker (E5)
Nothing to change: a suspended or over-cap call is already message-only on the worker, and the worker already says the returned `sayToCaller`. If a call somehow runs past 20 minutes its tool calls get 401, which the worker already maps to its "trouble, try again" line.
