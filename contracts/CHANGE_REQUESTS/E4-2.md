# E4-2: pronunciations for business, staff and service names in the resolved call

**From:** [1145:E4] · **To:** [1145:C0] (`contracts/openapi/tenant-tools.yaml`, `packages/shared`)

## What
Add two optional fields to `ResolvedCall.agent` (additive, nothing breaks):

```yaml
pronunciations:
  type: array
  maxItems: 50
  description: Owner-confirmed names the voice tends to say wrong. Spoken only; never shown to the model.
  items:
    type: object
    required: [text, sayAs]
    properties:
      text:  { type: string, maxLength: 80, description: 'As written, e.g. "Kemi Cuts"' }
      sayAs: { type: string, maxLength: 80, description: 'Spelled how it sounds, e.g. "Keh-mee Cuts"' }
pronunciationDictionary:
  type: object
  description: ElevenLabs pronunciation dictionary created by provisioning from `pronunciations` (optional).
  required: [id, versionId]
  properties:
    id: { type: string }
    versionId: { type: string }
```

## Why
Callers notice immediately when the agent mangles the business's own name or the owner's name; it's one of the
fastest "this is a robot" tells. E4 ships the runtime side in `frontdesk/voice_config.py`:
- `alias_transform()` / `tts_text_transforms()`: a streaming TTS text transform that swaps names for their
  `sayAs` spelling. Works with no ElevenLabs provisioning at all; only needs `pronunciations`.
- `elevenlabs_alias_rules()` / `pronunciation_dictionary_request()`: the body for ElevenLabs
  `add-from-rules` (alias rules, which work on Flash). Provisioning would create it and store
  `pronunciationDictionary`; `pronunciation_locators()` turns that into the TTS argument.

Onboarding can collect these with one natural question ("Any names people usually say wrong? Tell me how they sound.").

## Local fake
E4's tests build `Pronunciation(text, say_as)` lists directly; `ResolvedTenant` (E5) would map
`agent.pronunciations[*].{text,sayAs}` onto them.
