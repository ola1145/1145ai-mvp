# E7-1: ElevenLabs webhook receiver: caller number, duplicate deliveries, a shared dedupe store

**From:** E7 (`engines/elevenlabs-adapter`) · **To:** C0 (`packages/shared`), the owner of the ElevenLabs webhook receiver (none exists yet), G3 (post-call)
**Status:** open, not blocking. The adapter works without any of it.

## 1. `NormalizedCallEvent.callerE164?` (C0, `packages/shared/src/voice-engine.ts`) — from CR G2-3 part 2
`ElevenAgentsEngine.normalizeCallEvent` now returns `ElevenCallEvent = NormalizedCallEvent & { callerE164?: string }`.
`callerE164` is the carrier caller ID of an inbound call, normalised to E.164, read from
`data.metadata.phone_call.external_number` when `direction === 'inbound'`. It is left out for outbound calls, missing
or withheld numbers, and never comes from the transcript. Please add the same optional field to `NormalizedCallEvent`
so the receiver does not need the adapter's type.

The receiver should store it the way the LiveKit worker does (CR G2-3): in the tenant-scoped transcript object
(`tenants/<tid>/transcripts/<callId>.json`, tagged `kind=transcript`), never on the event bus, because events mask phone
numbers by contract.

Unverified: the payload path is from the ElevenLabs API definition. No inbound call has been recorded yet, so the first
real inbound call on the fallback engine (W0-03 spike) should confirm it. If the path is wrong the field is simply absent.

## 2. Duplicate deliveries (SEC-30)
`normalizeCallEvent` now throws `DuplicateEventError` for a second delivery of the same `conversation_id` inside ten
minutes (after the signature and the agent-to-tenant check have passed). The receiver should answer 200 and drop it.
If handing the event on fails (for example EventBridge is down), call `engine.releaseEvent(callId)` before answering
with an error, or the provider's retry is dropped as a duplicate and the call never ends in our records.

## 3. A store shared between instances
The default `MemoryEventDedupe` covers one Lambda instance. Post-call is idempotent on the call id, so a duplicate that
slips through costs nothing, but if the team wants the check to hold across instances, pass an `EventDedupe` whose `claim`
is a DynamoDB conditional put (`PK = WEBHOOK#elevenlabs`, `SK = <conversation_id>`, `ttl` = now + `ttlSec`) and whose
`release` deletes the item. The adapter does not declare the AWS SDK, so it takes the store as a port.

## 4. D8-3 (for information)
`placeSmokeTestCall` returns the ElevenLabs `conversation_id`, the same value `normalizeCallEvent` uses as `callId`.
When ElevenLabs answers success without a conversation id the call now throws instead of returning the SIP call id,
because that id never appears on the webhook and the smoke call could not find its result.
