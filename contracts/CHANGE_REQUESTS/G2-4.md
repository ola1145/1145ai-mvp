# G2-4: declare the Secrets Manager client post-call already uses at runtime (owner: P3, `services/post-call/package.json`)

**From:** G2 (`services/post-call/src/stripe-usage.ts`) · **To:** P3 (dependency lists) · **Blocking:** no

Kind: dependency

- npm: `@aws-sdk/client-secrets-manager@^3.700.0` in services/post-call

## Why
`createStripeUsage(env)` reads the Stripe key from the secret named by `STRIPE_SECRET_ID` the first time a tenant with a
Stripe customer is billed. `services/post-call/package.json` does not list the client, so the code loads
`@aws-sdk/client-secrets-manager` by name at that moment instead of importing it at the top of the file. That works today
because the bundle leaves `@aws-sdk/*` external (see `infra/cdk/lib/lambda.ts`) and the nodejs22 Lambda runtime ships every
v3 client; it would not type-check as a normal import without the dependency.

## After it lands
Replace the by-name load (`secretsManagerReader` in `stripe-usage.ts`) with a normal import of `SecretsManagerClient` and
`GetSecretValueCommand`. Nothing else changes: the tests inject the secret reader, and no test or deploy depends on this.
The other lanes that read secrets (channels, notifications, provisioning, control-plane, tool-api) already declare it.
