# G3-3: caller number in the transcript object, and the post-call items in `keys.md` (owners: E2, C0)

**From:** G3 · **Status:** open, not blocking. Everything below degrades cleanly without it.

## Part 1 (E2, `engines/livekit-agent/src/frontdesk/events.py`): add `callerE164` to the transcript object
The customer record is merged by phone, but nothing post-call can read carries the caller's number:
`call.ended` has none, `call.started` only has `callerMasked`, and the transcript object is
`{ callId, tenantId, roomName, turns }`. The worker has the number (`sip.phoneNumber`, normalised by
`sip.normalize_e164`).

Proposed: add one optional field to the S3 object written by `CallEvents._upload_transcript`:
```json
{ "callId": "call-7f3a", "tenantId": "t_tenanta01", "roomName": "call-7f3a", "callerE164": "+12145550123", "turns": [] }
```
Only when the number normalises to E.164; omit the field otherwise (web chat has none). It goes in the transcript object,
not in `call.ended`, because events reach the dashboard and the object is tenant-prefixed, KMS-encrypted and expires
after 90 days. G3 already reads it (`parseTranscript` in `services/post-call/src/deps.ts`) and re-checks the format.
Until E2 adds it, G3 calls `upsertCustomerFromCall` without a phone.

## Part 2 (C0, `contracts/dynamodb/keys.md`): two additions, both additive
| Entity | PK | SK | Notes |
|---|---|---|---|
| Post-call ledger | `TENANT#<tid>` | `POSTCALL#<callId>` | One per finished or in-progress `call.ended`. `step_<usage\|usageEvent\|stripe\|analysis\|crm\|live>` (ISO time, present once that step is done), `usage {seconds, usedSec, capSec}`, `analysis {summary, sentiment, intents, callerE164?}`, `leaseOwner`, `leaseUntil` (epoch s; 0 = released), `ttl` (60 days). Written by the post-call Lambda only. |

and, on the existing **Conversation** row (`CONV#<startIso>#<convId>`), the attributes post-call writes besides the
ones already listed: `callId`, `durationSec`, `endReason`, `intents[]`, `naturalnessScore`, `worstTurnScore`,
`flaggedTurns[] {turn, text (<= 500 chars), score, issues[{rule, severity, detail}]}` (agent turns that tripped a
conversation-style rule, kept for the quality review), `analyzedAt`. `convId` is the call id; `<startIso>` is the
`call.ended` `occurredAt` minus `durationSec`, so a replay writes the same item. `transcriptKey` is always under
`tenants/<tid>/transcripts/`.

## Part 3 (C0, `contracts/events/events.schema.json`): note only
`usage.recorded` and `conversation.message` are published by post-call with `Source: 1145.post-call` and the envelope
as `Detail`. `usage.recorded.engine` is always `livekit-telnyx` for now: the LiveKit worker is the only thing that puts
`call.ended` on the bus. When the ElevenLabs webhook path does, `call.ended` needs an explicit engine field (additive,
optional) so post-call can label the usage; `engineConversationId` is not defined to mean "ElevenLabs", so G3 does not
infer it. No schema change today.
