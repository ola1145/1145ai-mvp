# G2-1: document the attributes and guard items post-call reads and writes

**From:** G2 (CRM upsert, usage counter, Stripe usage) · **Needs:** contracts owner (P3) for `contracts/dynamodb/keys.md` and `contracts/events/events.schema.json`

Nothing here blocks G2. The code works against these names today; this request is so every other lane sees the same ones.

## 1. Tenant profile (`TENANT#<tid>` / `PROFILE`)
Read by `usage-store.ts` and `stripe-usage.ts`. Add to the profile row (H2-2 already adds `numbers`, `state`, `stateReasonCode`, `stateActor`, `stateUpdatedAt`):

| Attribute | Type | Meaning |
|---|---|---|
| `capSec` | number | Seconds of talk time the tenant may use per month before calls go to "take a message". When absent, post-call uses 1800 (the 30 free trial minutes). Written by billing/provisioning when a plan is set. |
| `stripeCustomerId` | string `cus_...` | The tenant's Stripe customer. Written by the payment-setup / billing lane (D9, H1). Absent before a card is on file, and post-call then skips Stripe usage for the tenant. |

## 2. Usage item (`USAGE#<yyyy-mm>`)
`billableSeconds` (number, atomic ADD), `callCount` (number, atomic ADD), `updatedAt` (ISO). The month is the UTC month the call ended in. H2-2 point 4 already names `billableSeconds`.

## 3. Customer item (`CUSTOMER#<cid>`)
Post-call creates customers the owner has not entered yet, and merges calls into ones they have (found through GSI1 `TENANT#<tid>#PHONE` / `<e164>`):

| Attribute | Written by | Meaning |
|---|---|---|
| `name`, `phones[]`, `email`, `notes` | owner (post-call only fills an empty `name` or missing `phones`; never `email` or `notes`) | |
| `ownerEditedFields` | owner dashboard / tool-api | string[] of field names the owner changed by hand (`name`, `phones`, ...). Post-call never fills a listed field, even if it is empty. Please set it whenever an owner edit is saved. |
| `lastSeen`, `lastCallId`, `lastCallSummary` | post-call | Moved forward only; `lastCallSummary` is model output, shown to the owner as data. |
| `callCount` | post-call | Atomic ADD, once per call id. |
| `createdBy: "call"`, `createdAt` | post-call | On customers created from a call. Their `cid` is `c_` + the first 20 hex characters of `sha256(e164)`, so two calls ending together cannot create two records. |

## 4. Per-call guard items
Written in the same DynamoDB transaction as the effect they guard, so a replayed `call.ended` cannot repeat it:
`TENANT#<tid>` / `IDEMP#usage:<callId>`, `IDEMP#crm:<callId>`, `IDEMP#stripe:<callId>` (the Stripe one holds `meterEventId`).
Their `ttl` is 45 days, not the 24 h in the `Idempotency` row: a replay can arrive long after the first delivery, and
Stripe accepts usage up to 35 days back. Please add them to the `Idempotency` row.

## 5. Events
- `tenant.state_changed` is emitted by post-call with `{ state: "over_cap", previousState: "active", reasonCode: "minutes_cap", actor: "system" }`, as the schema says. The H2 console emits `previous` instead of `previousState`; one of the two should change so consumers read one name.
- `usage.recorded.capThreshold` (`80 | 100`, from C6-2) is still not in `events.schema.json`. G2's `addUsage` result carries `crossed` (`80 | 100`, only on the call that crosses it) for G3 to copy into that field.

## 6. Stripe meter (ops note, not a file change)
Create one billing meter in the test-mode Stripe account: event name `voice_seconds`, aggregation `sum`, customer key `stripe_customer_id`, value key `value`. Each call sends its billable seconds. The included minutes and the per-minute overage belong in the price (tiered, graduated), not in code.
