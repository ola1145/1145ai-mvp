# T5-2: PROFILE attributes the resolver reads, a 503 on both resolver routes, and one shared ABAC client

**From:** T5 (resolvers). **Needs:** contracts owner (C0) for `keys.md` and the two OpenAPI files; the lane that writes PROFILE
(D7 render step, D-series agent-name step); T7 for `ddb-repo.ts`.

## 1. PROFILE attributes (`contracts/dynamodb/keys.md`, Tenant profile row)
The resolver reads exactly these from `TENANT#<tid>` / `PROFILE` (with a projection, so nothing else is loaded) and caches the
result 60 s per tenant:

| Attribute | Written by | Used for |
|---|---|---|
| `renderedInstructions`, `renderedDisclosureLine` | render-agent step (`RenderedRecord`) | `agent.instructions`, `agent.disclosureLine` |
| `templateVersion` | render-agent step | `agent.templateVersion` |
| `name` (also accepted: `businessName`) | onboarding | `agent.businessName` |
| `timezone` | onboarding | `agent.timezone` (must be a valid IANA zone) |
| `agentName` (default `Ava`), `voiceId` (optional), `language` (default `en-US`) | agent-name step / owner edits | `agent.agentName`, `agent.voiceId`, `agent.language` |
| `state` | control plane `writeState` | `suspended` or `over_cap` here wins over an `active` route; any other value (for example `provisioning`) is ignored so the post-bind smoke test call still works |

The DynamoDB `ProfileStore.saveRendered` for the render step does not exist yet (`render-agent.ts` is still a stub), so these
names are T5's reading of `RenderedRecord` and `ProfileSnapshot`. Please make the writer use them verbatim.

## 2. A 503 on both resolver routes (`tenant-tools.yaml` `/internal/resolve/number`, `channels.yaml` `/internal/resolve/widget`)
Add `'503': { description: 'Tenant has no rendered agent yet (number or widget exists, PROFILE is missing a required attribute). Body is Error; sayToCaller is a natural "still getting set up" line.' }`.
The voice worker already maps any 5xx to its "hiccup, try again in a few minutes" line, and the 5xx alarms will show a tenant stuck
half-provisioned instead of hiding it behind a 404.

## 3. One cached ABAC client (`services/tool-api/src/lib/ddb-repo.ts`, T7)
`resolver-deps.ts` has to read PROFILE through a tenant-scoped client (ADR-0003: the execution role may read route items only),
but `ddb-repo.ts` keeps its cached provider private and `TenantRepo` has no profile read. T5 therefore builds a second provider
with the exported `createTenantDocProvider`, which costs one extra AssumeRole per tenant per warm container (~14 min).
Proposed: export the existing `prodProvider` (for example `export const tenantDocFor = prodProvider;`) or add
`getRuntimeProfile?(): Promise<Record<string, unknown> | undefined>` to `TenantRepo`. Then T5 deletes its provider (marked
`TODO(T5-2)` in `buildProdDeps`).
