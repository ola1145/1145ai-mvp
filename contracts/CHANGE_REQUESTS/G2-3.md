# G2-3: give post-call the caller's phone number so the CRM can merge by it

**From:** G2 · **Needs:** E2 (`engines/livekit-agent/src/frontdesk/events.py`), E-lane owner of the ElevenLabs adapter, and G3 (`loadTranscript` / `callerFor`)

## The gap
The CRM merges customers by phone, but post-call cannot learn the number. `call.ended` carries `callId`, `durationSec`,
`endReason`, `transcriptKey` and no caller (events mask phone numbers by contract), and the transcript object in S3 is
`{ callId, tenantId, roomName, turns }`. `call.started` has only `callerMasked`. Until a number reaches post-call,
`makeUpsertCustomerFromCall` finds no phone and skips the customer step; usage and Stripe are unaffected.

## Proposed change
1. E2: write `callerE164` into the transcript object, next to `callId` (`{ "callId", "tenantId", "roomName", "callerE164", "turns" }`).
   Use the same verified SIP caller id the worker already feeds to `callerMasked`. Omit it when the call has no usable
   number (web chat, withheld caller id). It must never come from anything the caller or the model said.
   The object is tenant-scoped and tagged `kind=transcript`, so the number stays off the event bus.
2. ElevenLabs adapter: `NormalizedCallEvent` has no caller field. If that engine's call records carry the caller number,
   add an optional `callerE164` there and store it the same way.
3. G3: have `loadTranscript` (or a sibling) return `callerE164` and feed it to `callerFor(tenantId, callId)` in
   `makeUpsertCustomerFromCall`. Keep the check that `transcriptKey` starts with `tenants/<envelope tenantId>/transcripts/` (SEC-14).

## Why not the model
The analysis step could extract a number from the conversation, but that is caller-controlled text. The CRM would then
merge into whichever customer a caller names. Caller ID is only a hint, but it is the carrier's hint, and G2 never
overwrites anything the owner has filled in.
