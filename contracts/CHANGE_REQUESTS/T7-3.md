## 1. P3: the two packages
The two lines at the top are in the format `scripts/ci/dep-batch.ts` reads (CR T0-1 item 3 and T7-2 item 1 asked in prose, which the batch cannot parse). `deps.ts` does not import them statically, because declared dependencies are frozen for lane agents. It loads them by name the first time knowledge search runs, so with the packages missing from both the bundle and the Lambda runtime the function keeps answering from keyword search (it logs the failed import once). After P3 lands them, T7 can replace `loadAwsSdk` with two static imports.

## 2. C0: `infra/cdk/lib/data-stack.ts`
`grantRouteRead` allows `NUMBER#*`, `IDENTITY#*`, `ENGINEAGENT#*`, `SIGNUP#*` and `REFERRAL#*`, but not `WIDGET#*`. The widget route (`PK = WIDGET#<key>`, `SK = ROUTE`) is read by `/internal/resolve/widget` (tool API, T5) and by the web chat token endpoint (`customer-webchat-token.ts`, C4, which is granted through `grantRouteRead`). The tool API resolver now gets its own `WIDGET#*` read in `api-stack.ts`, so it works; the channels function will get `AccessDeniedException` in a deployed stack until `WIDGET#*` is added to the `LeadingKeys` list there (the `iam-isolation` test may need the family listed too).
