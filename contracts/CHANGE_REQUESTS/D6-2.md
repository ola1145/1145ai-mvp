# D6-2: extra FACT# attributes written by the scraper, and plain-word reasons for every flag (from D6, knowledge scrape)

**Needs:** C0 (`contracts/dynamodb/keys.md` is a contract file), D3 (owner card), and the knowledge indexer (T0-1 item 4).

## What D6 writes
One item per candidate fact: `PK TENANT#<tid>`, `SK FACT#f_<16 hex>`. The id is a hash of `onboardingId + source + text`,
so scraping the same page twice produces the same items, and the write is `attribute_not_exists(PK)`: a re-run never
resets an owner decision (D3's `verified: true` / `decision`).

The contract row (`text, source, verified, flaggedInstructionLike`) is kept as is. Added attributes (additive only):

| Attribute | Type | Meaning |
|---|---|---|
| `flags` | string[] | Why it is flagged: `override, persona, prompt-ref, role-tag, exfil, tool-call, ai-addressed, directive, obfuscated`. Empty when clean. `flaggedInstructionLike` is `flags.length > 0`. |
| `kind` | `price` \| `hours` \| `info` | What the text looks like. Flagged items are always `info` (never parsed for prices or hours). |
| `label` | string? | Price only: what it is for, when the line says so plainly ("Haircut"). |
| `amountCents`, `maxAmountCents` | number? | Price only: the amount, or the low and high end of a range. A candidate, not a price anyone has confirmed. |
| `onboardingId` | string | The onboarding that scraped it. |
| `createdAt` | ISO string | When it was written (D3 orders the card by it). |

`source` is the URL of the page the text came from. `verified` is always `false` when written.

## Requested changes
1. **C0:** add the attributes above to the "Knowledge fact" row of `contracts/dynamodb/keys.md`.
2. **D3:** already compatible with `flags`, `flaggedInstructionLike` and `createdAt`. One gap: D3's own reason map
   covers six flags, so `ai-addressed`, `directive` and `obfuscated` fall back to the generic reason. D6 exports
   `FLAG_REASONS` from `services/provisioning/src/lib/sanitize.ts` with owner-facing wording for all nine (checked against
   conversation-style in `sanitize.test.ts`). Import it instead of keeping a second copy, or copy the three missing lines.
3. **D3 (informational):** `kind: 'price'` candidates become something the agent will quote once approved. Prices already need
   step-up elsewhere (`1145-tenant-isolation`); consider not letting one blanket "yes" approve price facts.
4. **Knowledge indexer (T0-1 item 4):** index only `verified: true` facts as `verified: true`; everything D6 writes starts
   `verified: false`, so it must not be searchable by the customer agent until the owner approves it.
