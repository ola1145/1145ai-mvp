# G2-2: wire the G2 stores into the post-call handler, deps and stack

**From:** G2 · **Needs:** G3 (owner of `services/post-call/src/handler.ts`, `deps.ts`, `usage.ts`, `package.json`, `infra/cdk/lib/postcall-stack.ts`)
**Status:** applied in [1145:G2] (claude/1145-g2-w2) and [1145:G3] (claude/1145-g3-w2), merged-integration reconcile of G3-1 and this request.

## Outcome: one interface, G3-1's factory shape
G2 and G3 built against different shapes. They now agree on the one in G3-1 (the Lambda builds each port once per warm
container from one environment), because it needs no per-event rebuild and keeps `deps.ts` the only place that knows AWS:

| Module | Export | Port |
|---|---|---|
| `crm.ts` | `createCrm(env)` | `upsertCustomerFromCall(tenantId, callId, summary, caller?: { phone?, at? })` |
| `usage-store.ts` | `createUsageStore(env)` | `addUsage(tenantId, callId, seconds, at?)` returns `{ usedSec, capSec, crossed?, replayed, stateChanged, month }` |
| `stripe-usage.ts` | `createStripeUsage(env)` | `reportUsage(tenantId, callId, seconds, at?)` |

`env` is `G2Env` from `deps.ts` (`db`, `table`, `publish`, `now`, `stripeSecretId`). `at` is the event's `occurredAt` (the
month a call is filed under and the time Stripe is given); it is optional so a caller without it still works, falling back
to `env.now()`. `docFor` and `routeDoc` are both the Lambda's own client: the Lambda role is limited by IAM to `TENANT#*`
keys and `UpdateItem` on `NUMBER#*` (ADR-0003 has no per-tenant role for a platform Lambda). `makeAddUsage`,
`makeUpsertCustomerFromCall`, `makeReportStripeUsage` and `CallerFacts.callerFor` are gone. Everything below this line is
the original proposal; the guarantees (per-call guard items, one over_cap flip and one `tenant.state_changed`, Stripe key =
call id) are unchanged and are exercised through the real handler path in `services/post-call/test/usage-store.test.ts`.

G2 ships three modules with a DynamoDB implementation, a fake-friendly port and a `PostCallDeps` adapter each. They
are idempotent on their own, so `alreadyProcessed` stays as the first line of defence and these are the second: three
deliveries of the same `call.ended` give one counted call, one customer update, one Stripe event and one
`tenant.state_changed`.

Returns `{ usedSec, capSec }` plus `crossed` (`80 \| 100`), `replayed`, `stateChanged`, `month`. ## Asks for `handler.ts`
1. `PostCallDeps.addUsage(tenantId, seconds)` has no call id or time. Either build the deps per event (as `makeAnalyze(tenantId, callId, deps)` already does) so `makeAddUsage(callId, at, ...)` can bind them, or change the signature to take them.
2. Add the Stripe step after `addUsage` (a `reportStripeUsage(tenantId, seconds)` dep is enough).
3. Copy `usage.crossed` into `usage.recorded` as `capThreshold` (C6-2: "set only on the event that crosses the threshold"). Without it the owner never hears "80% used" or "minutes used up".
4. A failed step should throw (not swallow), so EventBridge retries; the guards make the retry safe.

## Asks for `deps.ts` and `postcall-stack.ts`
- `docFor(tenantId)` must be the ABAC client (AssumeRole with session tag `tenant_id`, see `createTenantDocProvider` in tool-api). G2 only ever touches `TENANT#<tid>` through it, plus GSI1 queries on `TENANT#<tid>#PHONE`. Needed actions: `GetItem`, `Query` (GSI1), `PutItem`, `UpdateItem` (transactions need no extra action).
- `routeDoc` is a plain client for the one thing outside the tenant partition: `UpdateItem` on `NUMBER#*` / `ROUTE` items (the over_cap flip, conditional on `tid` and `state`). The resolver role is read-only, so post-call's role needs `dynamodb:UpdateItem` with `LeadingKeys` limited to `NUMBER#*`, and KMS use on the table key.
- Stripe: read `STRIPE_SECRET_KEY` (a test-mode `sk_test_` or `rk_test_` key) from Secrets Manager. `createStripeUsageClient` throws on a live key unless `{ allowLive: true }` is passed, so switching to live is a deliberate code change. The Lambda needs outbound HTTPS to `api.stripe.com`.
- No new dependencies: `stripe`, `@aws-sdk/lib-dynamodb` and `@1145/shared` are already declared in `services/post-call/package.json`.

## Known gaps G2 does not close
- Nothing resets `over_cap` at the start of a new month or when a plan's `capSec` is raised. A tenant stays on "take a message" until something flips it back. The control plane (H lane) or a monthly scheduled job should reopen tenants whose `stateReasonCode` is `minutes_cap` and whose usage is below the cap. It must never reopen one that ops suspended.
- If publishing `tenant.state_changed` fails right after the flip, the call.ended retry sees the tenant already `over_cap` and does not emit it again. The state itself is correct and `usage.recorded` still goes out; only the fleet-view event is lost.
- `crossed` is computed from the month total minus this call, so two calls ending in the same instant can both report a crossing. It is an owner notice, not a billing figure.
