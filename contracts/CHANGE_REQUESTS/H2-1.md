# H2-1: export a shared audit writer from services/control-plane/src/audit.ts (owner: H1)

**From:** H2 (admin console API) **To:** H1 **Status:** open, not blocking

## What
`services/control-plane/src/audit.ts` is still a stub whose only export is a Lambda `handler` that throws. The console
needs a plain function that writes one audit entry to the Object Lock bucket.

## Why
Every console write must land in the audit bucket with a reason code and an actor. Until H1 ships a writer, H2 carries
a local one at `services/control-plane/src/console/audit-sink.ts` (JSON object, `Content-MD5`, key
`audit/<yyyy>/<mm>/<dd>/<tenantId>/<iso>-<uuid>.json`). Two writers means two key layouts in one bucket.

## Proposed change
In `audit.ts`, export:

```ts
export interface AuditEntry { tenantId: string; action: string; reasonCode: string; actor: string; at: string;
  requestId?: string; supportCaseId?: string; note?: string; detail?: Record<string, unknown> }
export function auditWriter(s3: Pick<S3Client, 'send'>, bucket: string): (e: AuditEntry) => Promise<void>;
```

It must throw when the put fails. H2 will delete `audit-sink.ts` and import this one. If H1 prefers a different key
layout, H2 follows it. The `AuditEntry` fields above are what the console already writes; `setTenantState` in
`set-tenant-state.ts` uses the first five.
