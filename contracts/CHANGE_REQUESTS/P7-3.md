# P7-3: wire the queues, APIs and alarm email into ObservabilityStack (owner: P2, `infra/cdk/bin/app.ts`)

**What.** `ObservabilityStack` now takes optional props. `bin/app.ts` currently passes only `{ env }`, so the
5xx, DLQ and FIFO-age alarms and widgets have nothing to watch yet. Proposed change:

```ts
// ChannelsStack: expose `readonly inboundDlq: sqs.Queue; readonly inbound: sqs.Queue; readonly hooksApiId: string;`
// ApiStack:      expose `readonly apiId: string;` (api.apiId)
const channels = new ChannelsStack(...);   // keep the const
new ObservabilityStack(app, p('observability'), {
  env,
  alarmEmail: app.node.tryGetContext('alarmEmail'),
  apiIds: [api.apiId, channels.hooksApiId],
  dlqs: [channels.inboundDlq],
  fifoQueues: [channels.inbound],
});
```

Lanes that add a queue or API later add it to these arrays. Prod synth fails without `-c alarmEmail=...`, and the
deploy workflow should pass it from an `ALARM_EMAIL` environment variable (`.github/**`).

**Why.** Without it the stack has only the always-on alarms (failed calls, per-route p95, account-wide Lambda errors).

**Note.** This makes ObservabilityStack depend on the api and channels stacks via cross-stack references; it is
last in the app, so nothing depends on it. Removing a queue or API later means removing it from these arrays in the
same deploy.
