# T5-1: define the widget route item, and let the resolver role read it

**From:** T5 (resolvers). **Needs:** contracts owner (C0) for `keys.md` and `packages/shared/src/keys.ts`; infra owner of
`infra/cdk/lib/data-stack.ts`; whoever issues widget keys (provisioning or the dashboard) to write the item.

## What is missing
`POST /internal/resolve/widget` and `POST /v1/webchat/token` both turn a public widget key (`wk_...`) into a tenant, but
nothing says where that mapping lives. T5 reads, and C4's tests (`services/channels/test/webchat-token.test.ts`,
`createWidgetLookup`) read, the same item. They agree, so this CR only writes it down and fixes the permissions.

## Proposed change
1. `contracts/dynamodb/keys.md`, new row next to the other route items:

   | **Route: widget** | `WIDGET#<widgetKey>` | `ROUTE` | `tid` (string, required), `enabled` (boolean; **only an explicit `true` opens the widget**, anything else or absent is a 404), optional `state` (`active`, `suspended`, `over_cap`; the resolver returns the stricter of this and `PROFILE.state`), optional `businessName` and `agentName` (read by the token endpoint for the greeting). `widgetKey` matches `^wk_[A-Za-z0-9]{16,40}$`. Resolver and token-endpoint roles only. |

   and add `WIDGET#*` to the list of route prefixes in the IAM paragraph.
2. `packages/shared/src/keys.ts`, in `keys`: `widgetRoutePk: (widgetKey: string) => 'WIDGET#' + seg(widgetKey, 'widgetKey')`.
   Until then T5 builds the key the same way, after checking the pattern above (`resolver-deps.ts`).
3. **`infra/cdk/lib/data-stack.ts`, `grantRouteRead`: add `'WIDGET#*'` to the `dynamodb:LeadingKeys` list.** Without it the
   `internal-resolve-widget` Lambda (and the web chat token Lambda, which also uses `grantRouteRead`) gets AccessDenied on
   the GetItem, so web chat answers 500 in dev even though every unit test is green. This is the one item that blocks the
   widget path end to end.
4. Writer: the lane that issues a tenant's widget key writes `WIDGET#<key>/ROUTE` with `tid` and `enabled: true` in the same
   step that shows the owner the embed snippet, and sets `enabled: false` to disable it. Nobody writes it yet.
5. Control plane (optional): `consoleEngineFor.setTenantState` flips `state` on `NUMBER#` routes only. The widget path takes a
   suspension from `PROFILE.state` (written by `writeState`), cached up to 60 s, so web chat follows the kill switch within a
   minute. If it must be instant, also update the tenant's `WIDGET#` routes there.
