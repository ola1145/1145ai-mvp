# C6-1: DynamoDB keys for owner notifications

**From:** C6 (owner notifications) · **Touches:** `contracts/dynamodb/keys.md` (owner: P3), `packages/shared/src/keys.ts`

## What
Document the items the notification dispatcher reads and writes. All live under `TENANT#<tid>`, so the existing
tenant IAM design holds. The dispatcher is a platform Lambda; its role is limited to `TENANT#*` leading keys.

| Entity | PK | SK | Attributes |
|---|---|---|---|
| Notification prefs | `TENANT#<tid>` | `NOTIFY#PREFS` | `events` {eventType: ["telegram"\|"email"\|"push"]}, `quietHours` {start:"HH:MM", end:"HH:MM"} (tenant timezone), `urgentCall` bool (default true), `urgentCallInQuietHours` bool (default true) |
| Push subscription | `TENANT#<tid>` | `NOTIFY#PUSH#<sha256(endpoint)[0..24]>` | `endpoint`, `p256dh`, `auth` (written by the owner app's subscribe call; the dispatcher deletes it when the push service says 404/410) |
| Dedupe claim | `TENANT#<tid>` | `NOTIF#<eventId>#<channel>#<hash12>` | `ttl` = now + 7 days. Written with `attribute_not_exists(PK)`; released if the send failed so a redelivery retries only that target |

Also, the `MEMBER#<sub>` item for the owner needs these attributes for contact details (the dispatcher reads only
`role = "owner"` members): `email`, `phone` (E.164, used only for the urgent call), `identities: [{channel: "telegram", id: "<chat id>"}]`.

## Why
Preference routing, quiet hours, per-event dedupe and web push all need somewhere to live. Keeping them under the
tenant partition avoids new IAM rules.

## Proposed change
Add the three rows above to `contracts/dynamodb/keys.md`; add `notifyPrefsSk`, `pushSubSk(endpoint)` and
`notifClaimSk(eventId, channel, hash)` builders to `packages/shared/src/keys.ts` (C6 keeps local copies in
`services/notifications/src/store.ts` until then). Whoever builds the owner app's "turn on notifications" call
should store the subscription at `pushSubscriptionSk(endpoint)` exported from the store, so removal finds it.
