# C1-2: wiring the router needs from `infra/cdk/bin/app.ts` and shared stacks

From: C1 (router). To: P2 (owner of `infra/cdk/bin/app.ts`), P-lane owning `data-stack.ts` and `api-stack.ts`.

## 1. `bin/app.ts`: pass two optional props to `ChannelsStack`
```ts
const realtime = new RealtimeStack(app, p('realtime'), { env, auth, events });
...
new ChannelsStack(app, p('channels'), { env, data, events, auth, realtime, toolApiUrl: api.url });
```
`ChannelsStack` accepts both as optional today. Without `realtime` the router gets `appsync:EventPublish` on any API's `owners`
namespace (via a wildcard) and reads the domain from `-c eventsHttpDomain=...`; without `toolApiUrl` it reads `-c toolApiUrl=...`.
The router needs `EVENTS_HTTP_DOMAIN` (owner chat replies) and `TOOL_API_URL` (`CONFIRM 1234` goes to `/v1/admin/changes/apply`).

## 2. Signing secret must be one value
The router signs tenant tokens with `TOOL_API_TOKEN_SECRET_CURRENT` from the runtime secret `1145/<stage>/runtime` (what
`scripts/secrets/push.sh` writes). The tool API currently reads `tokenCurrent/tokenPrevious` from `ApiStack`'s own `ToolApiSecret`.
Those two must hold the same value, or the tool API will reject every router-minted token. Simplest: have `ApiStack` read the
runtime secret too (keys `TOOL_API_TOKEN_SECRET_CURRENT`, `TOOL_API_TOKEN_SECRET_PREVIOUS`).

## 3. `DataStack.grantRouteRead` has no KMS grant
The table uses a customer-managed key, but `grantRouteRead` only adds DynamoDB actions. The router adds
`table.encryptionKey.grantEncryptDecrypt(...)` itself; other route readers (resolver, tool API) likely need the same. Suggest doing it inside
`grantRouteRead`.

## 4. SSM parameters expected from A1
`/1145/<stage>/agentcore/onboarding-arn` and `/1145/<stage>/agentcore/admin-arn` (as in `agents/deploy/README.md`). `ChannelsStack`
resolves them at deploy time, so `cdk deploy` of the channels stack fails until A1 has published both.
