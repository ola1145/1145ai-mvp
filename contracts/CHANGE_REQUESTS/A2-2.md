# A2-2: Pin startProvisioning errors and the provisioningStatus shape (owner: D1/D9, `contracts/openapi/onboarding-internal.yaml`)

**What.** In `contracts/openapi/onboarding-internal.yaml`:

1. `POST /internal/onboarding/{onboardingId}/provisioning`: list the error codes. Today only `409 identity_not_confirmed`
   is documented. Proposed additions: `402 needs_payment_method` (no card on file; the workflow sends the card link
   in-channel) and `503 unavailable`.
2. `GET /internal/onboarding/{onboardingId}/provisioning`: add a response schema. The onboarding agent needs:
   ```yaml
   number: { type: string, description: E.164 }
   numberDisplay: { type: string, example: '(469) 555-0142' }
   forwarding:
     type: object
     properties:
       steps: { type: string, description: 'carrier-specific conditional-forwarding steps in plain words, owner-facing' }
   testCall: { enum: [pending, queued, done, failed] }
   ```

**Why.** The prompt tells the agent to give the owner their number and the forwarding steps from the status, and
never to guess carrier codes (Add-12). Without a pinned shape, the model has to guess field names. Without the error
codes, it can't tell "add a card first" apart from "something broke".

**Meanwhile.** `agents/onboarding/tools.py` treats any non-`identity_not_confirmed` error as "setup didn't go through,
don't promise a number". The A2 tests fake the status as the shape above.
