# D4-2: infra the signup lambdas need (from D4)

From: D4. To: owner of `infra/cdk/lib/provisioning-stack.ts` (D5/P2) and `infra/cdk/lib/auth-stack.ts` (P5).

`Api-signup-link` and `Api-signup-callback` are built and tested with fakes. To run in dev they need this wiring, none of which D4 may edit.

## 1. Lambda environment (both functions)
| Variable | Value |
|---|---|
| `TABLE_NAME` | already set |
| `RUNTIME_SECRET_ID` | the runtime secret `1145/<stage>/runtime` (keys `TELEGRAM_BOT_TOKEN`, `ONBOARDING_SERVICE_TOKEN`, written by `scripts/secrets/push.sh`) |
| `COGNITO_DOMAIN` | hosted UI host only, no scheme: `ai1145-<stage>.auth.<region>.amazoncognito.com` |
| `COGNITO_CLIENT_ID` | the app client the owner app already uses (`AuthStack.userPoolClient`) |
| `SIGNUP_REDIRECT_URI` | `${onboardingApi.apiEndpoint}/signup/callback` |

If any is missing the handler answers `500 misconfigured` (link) or a plain "something went wrong" page (callback). It never builds a link from a guess.

## 2. IAM (both functions)
- `dynamodb:GetItem`, `dynamodb:PutItem`, `dynamodb:UpdateItem` on the table with `dynamodb:LeadingKeys` in `SIGNUP#*`, `ONBOARDING#*`
  (the callback's transaction needs the Update permission on both prefixes), plus the table CMK (`grantEncryptDecrypt`, as `allowItems` does).
  The callback does not need `PutItem`.
- `secretsmanager:GetSecretValue` on the runtime secret.
- No other permissions. In particular no `TENANT#*`.

## 3. Cognito (auth-stack)
- Add `${onboardingApi.apiEndpoint}/signup/callback` to the app client's `oAuth.callbackUrls`, with the authorization-code grant and scopes
  `openid email profile` only. The callback sends PKCE (S256) and no client secret.
- Do not map anything onto `custom:*` attributes (unchanged).

## 4. Route parameter name
The stack declares `/internal/onboarding/{id}/signup-link`; the contract says `{onboardingId}`. D4 accepts either, and falls back to parsing `rawPath`.
Please align the stack to `{onboardingId}` so every handler can read the same name.

## 5. Public callback hardening (SEC-25)
`GET /signup/callback` is public. Add stage throttling on the onboarding HTTP API (the callback does one DynamoDB read, one Cognito call and one
conditional write per request, and does no Google work for a spent or unknown link).

## 6. Telegram sender and service token (informational)
- `createTelegramPoster` in `signup-link.ts` is a small local sender (link previews off, retry 429/5xx). When C2's `telegram-send.ts` exports a
  shared one, D4 will switch to it; tell D4 the export name.
- The service token is the static `ONBOARDING_SERVICE_TOKEN` compared in constant time, matching what `agents/onboarding/app.py` sends today.
  SEC-22 (a per-invocation signed token with an `onb` claim) replaces `serviceTokenAuthorizer`; its `authorize(authorization, onboardingId)` signature already carries the id for that check.
