# G3-1: the module interface G3 calls in G2's files (owner: G2)

**From:** G3 (post-call handler wiring) · **Needs:** G2 (`crm.ts`, `usage-store.ts`, `stripe-usage.ts`)
**Status:** open, not blocking. G3 is tested against a fake of exactly this shape; until G2 lands the Lambda refuses to
start (see "Until then").

## Why
G2's three files are `handler()` stubs and its brief names no function signatures, so G3 has nothing to import. The old
`PostCallDeps` (pre-G3) guessed `addUsage(tenantId, seconds)` and `upsertCustomerFromCall(tenantId, callId, summary)`.
That `addUsage` has no call id, so a counter cannot recognise a repeat, and the crash window between "counted" and
"recorded that it was counted" would double-count a call on retry. The call id has to reach G2.

## The interface (`services/post-call/src/deps.ts` has the types: `G2Env`, `G2Ports`)
Each file exports one factory. G3 builds them once per warm container with the same environment:

```ts
interface G2Env {
  db: Pick<DynamoDBDocumentClient, 'send'>;   // the Lambda's own client; table access is granted per postcall-stack.ts
  table: string;
  publish(e: EventEnvelope): Promise<void>;   // EventBridge PutEvents on the 1145 bus, Source 1145.post-call
  now: () => Date;
  stripeSecretId?: string;                    // Secrets Manager name ("1145/stripe"); G2 fetches the value itself
}

// crm.ts
export function createCrm(env: G2Env): {
  upsertCustomerFromCall(tenantId: string, callId: string, summary: string, caller?: { phone?: string }): Promise<void>;
};
// usage-store.ts
export function createUsageStore(env: G2Env): {
  addUsage(tenantId: string, callId: string, seconds: number): Promise<{ usedSec: number; capSec: number }>;
};
// stripe-usage.ts
export function createStripeUsage(env: G2Env): {
  reportUsage(tenantId: string, callId: string, seconds: number): Promise<void>;
};
```

## What G3 relies on (please keep)
1. **Every call is safe to repeat for the same `(tenantId, callId)`.** G3 records each finished step and does not
   repeat it, but a crash between the call and the record means one repeat is possible. `addUsage` must count a call id
   once (e.g. a conditional marker item written in the same transaction as the counter increment) and return the
   current totals on a repeat. `reportUsage` uses the call id as the Stripe idempotency key. `upsertCustomerFromCall`
   must not add a second note or booking-count for the same call id.
2. `addUsage` returns the month's totals **after** this call; G3 turns them into the `cap` field of `usage.recorded`
   (`ok` / `warn` at 80% / `over`). `capSec` is the tenant's plan cap in billable seconds.
3. The over-cap flip is G2's: when a call takes the tenant to or past the cap, `addUsage` sets the `NUMBER#<e164>` route
   state to `over_cap` and publishes `tenant.state_changed` through `env.publish` (`state: 'over_cap'`,
   `previousState: 'active'`, `reasonCode: 'minutes_cap'`, `actor: 'system'`). The Lambda role has `dynamodb:UpdateItem`
   on `NUMBER#*` for this and nothing else on route items (no read; use a condition expression, not a read-then-write).
4. `caller.phone` is E.164, already format-checked by G3, and **absent** when the worker did not record one (see G3-3).
   `crm.ts` should still create or touch a customer in that case, or skip it, as G2 decides.
5. `summary` is model-written text from a caller-controlled transcript: store it as data, never as an instruction, and
   never use it as a key.
6. `tenantId` is always the verified envelope tenant. Nothing in `summary` or `caller` may choose the partition.

## Until then
`loadG2Ports` throws `usage-store.ts does not export createUsageStore(env)` (or the matching message) on the first
invocation. The event retries and then waits in the post-call DLQ; nothing is dropped and nothing is billed wrongly.
G3 deliberately does not ship a no-op stand-in, because a stand-in would let calls through unbilled.

## If G2 prefers different names
Say so on the issue and change `g2Modules`/`portFrom` in `services/post-call/src/deps.ts` (G3 owns it); the shapes above
are what matter.
