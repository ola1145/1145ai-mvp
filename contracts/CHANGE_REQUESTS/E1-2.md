# E1-2: protect the ECS task while a call is live (owner: E5, `engines/livekit-agent/src/frontdesk/worker.py`)

**From:** E1 · **Needs:** worker code in E5's module

## Why
Fargate waits at most 120 s (`stopTimeout`) between SIGTERM and SIGKILL. A deploy or scale-in would cut any call longer than that.
`voice-stack.ts` already grants the task role `ecs:UpdateTaskProtection` / `ecs:GetTaskProtection`.

## Proposed change
- When a job starts, call the ECS task-protection endpoint (`$ECS_AGENT_URI/task-protection/v1/state`, PUT `{"ProtectionEnabled": true, "ExpiresInMinutes": 60}`); when the job ends (and on error), set `ProtectionEnabled` false. Count live jobs so protection drops only at zero. Skip quietly when `ECS_AGENT_URI` is unset (local runs).
- Set the LiveKit `WorkerOptions` drain timeout high enough for a long call (for example 3600 s) so SIGTERM stops new dispatches but lets live jobs finish.
- A failure to set protection must never end or delay a call.
