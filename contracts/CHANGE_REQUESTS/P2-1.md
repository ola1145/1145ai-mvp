# P2-1: move the GithubOidcStack assertion test into infra/cdk/test

**From:** P2 (AWS bootstrap, OIDC roles, deploy pipeline). **To:** P4 (owns `infra/cdk/test/**`).

## What
P2's brief requires a CDK assertion test for `GithubOidcStack`, but P2 does not own `infra/cdk/test/**` and
`vitest.config.ts` only picks up tests from `infra/cdk/test`, `scripts/**/test` and similar folders.

To keep `make test` covering it, P2 parked the test at `scripts/secrets/test/github-oidc-stack.test.ts`. It imports
`aws-cdk-lib` through `scripts/secrets/test/cdk-lib.ts`, which re-exports it by relative path into
`infra/cdk/node_modules`, because `aws-cdk-lib` is a dependency of `infra/cdk` only.

## Proposed change (P4)
1. Copy `scripts/secrets/test/github-oidc-stack.test.ts` to `infra/cdk/test/github-oidc-stack.test.ts`.
2. In the copy, replace `import ... from './cdk-lib.js'` with
   `import { App } from 'aws-cdk-lib'; import { Match, Template } from 'aws-cdk-lib/assertions';`
   and the stack import with `../lib/github-oidc-stack.js`.
3. Tell P2 (or the owner) once it is merged; P2 then deletes the parked test and `cdk-lib.ts` in a follow-up.

No contract or shared type changes.

## What the test pins down
- Trust policy is `StringEquals` on `aud = sts.amazonaws.com` and `sub = repo:<repo>:environment:<env>`; no wildcards.
- One role per environment, 1 hour sessions, only `sts:AssumeRole` on the four CDK bootstrap roles of its own
  account and region, plus `ssm:GetParameter` on the bootstrap version parameter.
- `repo` must be `owner/name`; environment names must be plain words.
