# C5-1: what the referral redirect needs from `channels-stack.ts`, `keys.md` and the API stage

From: C5 (referral redirect, `services/channels/src/referral-redirect.ts`). To: C1 (owner of `infra/cdk/lib/channels-stack.ts`),
P3 (owner of `contracts/dynamodb/keys.md`), P2 (API stage settings).

Without item 1 the Lambda still redirects every visitor correctly, but every click write fails with AccessDenied (it is caught and
logged, so nothing breaks for the visitor and nothing is counted).

## 1. `channels-stack.ts`: let `ReferralRedirect` write click counts
Today it only gets `props.data.grantRouteRead(referral)` (read `REFERRAL#*`). It also needs, next to that line:

```ts
// Click log: the counter and per-visitor markers under REFCLICK#<code>. Nothing under TENANT#.
referral.addToRolePolicy(new iam.PolicyStatement({
  actions: ['dynamodb:PutItem', 'dynamodb:UpdateItem', 'dynamodb:DeleteItem'],
  resources: [props.data.table.tableArn],
  conditions: { 'ForAllValues:StringLike': { 'dynamodb:LeadingKeys': ['REFCLICK#*'] } },
}));
props.data.table.encryptionKey?.grantEncryptDecrypt(referral); // customer-managed table key (same as the router)
```

No `TransactWriteItems` and no `Query`: the handler uses single-item conditional puts, atomic adds and one marker delete.

Optional env per stage on that function (it defaults to production): `APP_START_URL` = `https://app.1145.ai/start` (prod) or
`https://app.dev.1145.ai/start` (dev). The handler accepts only https on `1145.ai` or a subdomain, no port, no credentials, and drops
any query or fragment. Anything else falls back to the production URL, so a bad setting cannot become an open redirect.

## 2. `contracts/dynamodb/keys.md`: document the click log
Extend the **Referral** row (additive, nothing renamed):

| Entity | PK | SK | Notes |
|---|---|---|---|
| Referral click counter | `REFCLICK#<code>` | `COUNT` | `clicks` (unique visitors, atomic add), `firstClickAt`, `lastClickAt`. Only written for codes that exist under `REFERRAL#<code>` |
| Referral click visitor | `REFCLICK#<code>` | `V#<visitorId>` | `at`, `ttl` = now + 30 days, `own: true` when the visitor was the referrer opening their own link. Conditional put `attribute_not_exists(PK)` is what makes a repeat click count once. No IP address or user agent is stored |

And add `REFCLICK#*` to the sentence listing what the redirect Lambda's role may write (read `REFERRAL#*`, write `REFCLICK#*`).

## 3. Throttle the public route (SEC-25, threat model F10 "click-log flooding")
`GET /r/{code}` is unauthenticated. A client that sends a fresh random `ref_v` cookie on every request gets one new marker and one
counter add per request for a real code. The handler cannot tell that from real traffic, so please add route throttling on
`/r/{code}` in the HTTP API stage (suggested starting point: 25 requests/s steady, 50 burst, per stage; tune from real traffic).
Counts are a funnel metric only. Rewards are decided by H3 on the first paid invoice, so a flood skews a chart and costs a little, but
cannot earn anything.

## Notes for whoever builds the other end
- The cookie is `ref_v`, `Path=/r`, `Secure`, `HttpOnly`, `SameSite=Lax`, 30 days. `Path=/r` assumes the public URL keeps the `/r/` prefix
  (`1145.ai/r/CODE`, as in `channels.yaml`). If the custom domain ever serves `r.1145.ai/CODE` instead, change `Path` in the handler.
- The redirect carries the code only as `?ref=<code>`. The web onboarding start page has to keep it through the Google sign-in round trip
  and send it as `referralCode` on the first owner-chat message (`apps/tenant-app/README.md`). The handler sets no cookie the app can read.
- "Self-referral" at click time means the referrer opening their own link from one of our own pages (browser `Sec-Fetch-Site` same-site or
  same-origin, or a `Referer` on `1145.ai`). That click redirects normally but does not count, and that browser stays uncounted for the
  code afterwards. A referrer who pastes their link into a browser that never visited it from inside the product looks like any other
  visitor at the redirect. Reward-time self-referral (same tenant, same identity, same card) stays with H3.
