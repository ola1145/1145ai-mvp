# C6-2: event `data` fields the notifications need

**From:** C6 (owner notifications) · **Touches:** `contracts/events/events.schema.json` (owner: P3), publishers of the events below

## What
Notifications read these optional fields from `data`. Everything is optional and treated as untrusted text; when a
field is missing the copy degrades gracefully ("New booking for tomorrow at 3.").

| Event | Fields |
|---|---|
| `booking.created`, `booking.cancelled` | `customerName`, `serviceName` (else the dispatcher looks up `SERVICE#<serviceId>`), `start` (ISO; a value with no offset is read as the tenant's local time) |
| `message.taken` | `callerName`, `callerMasked`, `message` (short summary or the message itself) |
| `handoff.requested` | `callerName`, `callerMasked`, `reason`, `urgent: true` (or `urgency: "urgent"`). Only an urgent handoff places a call to the owner |
| `usage.recorded` | `capThreshold: 80 \| 100`, set only on the event that crosses the threshold. Without it the event is not owner news |
| `tenant.state_changed` | `state` (`active`, `suspended`, `paused`; other values are ignored) |
| `tenant.provisioned` | `phoneNumber` (E.164) |

Also needed: a `booking.cancelled` and `handoff.requested` entry in `$defs` (only `booking.created` is described today).

## Why
"New booking: Tunde, haircut, tomorrow at 3." needs the name and service in the event, not just ids.

## Proposed change
Add the optional properties above to the matching `$defs` entries; have the tool API (bookings, takeMessage,
requestHandoff) and the usage meter include them.

## Ops note (not a contract change)
The dispatcher reads one Secrets Manager secret named `1145/notifications` (JSON: `telegramBotToken`, `resendApiKey`,
`emailFrom`, `vapidPublicKey`, `vapidPrivateKey`, `vapidSubject`, `telnyxApiKey`, `telnyxTexmlAppId`, `urgentCallFrom`).
Any key that is missing turns that channel into a logged no-op. Web push is implemented on `node:crypto` (verified
byte-for-byte against http_ece), so the `web-push` dependency in `services/notifications/package.json` is unused and
can be dropped by P3 whenever convenient.
