# Q1-1: wire the isolation suite into the tests/e2e project and its workflow

**From:** Q1 · **To:** P8 (owns `tests/e2e/package.json`, `.github/workflows/e2e.yml`)

## What
`tests/e2e` has no `package.json` yet, so `cd tests/e2e && npm run isolation` (the Q1 brief's run command) cannot exist
from Q1's owned paths. Please add to `tests/e2e/package.json`:

```json
"scripts": { "isolation": "vitest run --root isolation" }
```

and `vitest` (same version as the root, `^2.1.0`) to its devDependencies. Q1 adds no other dependency: SigV4, STS,
DynamoDB and AppSync are called with `fetch` and the Node 22 global `WebSocket`.

In `.github/workflows/e2e.yml`, run `npm run isolation` after the deploy and in the nightly job with
`ISOLATION_REQUIRE=1` (a skipped suite then fails the job) and the `ISOLATION_*` / AWS variables listed in
`tests/e2e/isolation/README.md`, sourced from secrets or the deploy outputs. The existing "if package.json is missing,
exit 0" shortcut should not apply to this step.

## Why
The brief requires the suite to run nightly and after deploys. Until this lands, the suite is runnable with
`pnpm vitest run --root tests/e2e/isolation` from the repo root.
