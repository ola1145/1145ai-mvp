# C4-3: somebody has to write the `WIDGET#<key>` route and the tenant's widget key

From: C4 (customer web chat token). To: D8 (`activate-tenant.ts`), D3 (agent naming), the lane that suspends or cancels tenants, and T5 (resolver).

## Gap
Nothing in the repo creates a widget key or the route item the token endpoint and `internal-resolve-widget.ts` read (shape in C4-1 section 1).
Without it every widget key is "unknown" and web chat answers 404, which is the safe failure but not a working feature.

## Proposed owners and behaviour
- **Create** (D8, at activation, next to the step that flips the `IDENTITY#` route): generate `widgetKey = "wk_" + 24 random base62 characters`
  from a CSPRNG (matches `^wk_[A-Za-z0-9]{16,40}$`, about 140 bits), then in one transaction put `WIDGET#<key>/ROUTE`
  `{ tid, enabled: true, businessName, agentName, createdAt }` conditional on `attribute_not_exists(PK)`, and store `widgetKey` on `TENANT#<tid>/PROFILE`
  so the owner dashboard can show the embed snippet. Idempotent: a retry reads `PROFILE.widgetKey` and reuses it.
- **Keep in step** (D3, when the owner renames the agent; the profile-edit path when the business name changes): update `businessName` / `agentName` on the route.
  Names are owner text, so they are cleaned as data by the token endpoint, but keep them short and single-line when writing them.
- **Disable** (suspend, cancel, owner turns the widget off): set `enabled: false` on the route (do not delete, so a re-enable keeps the same key already on the owner's site).
  A suspended tenant that is still `enabled` gets a room and the worker says the "paused" line (E5), which is fine; `enabled: false` gives the visitor "this chat isn't set up yet".
- **T5**: `internal-resolve-widget.ts` should read the same item and treat `enabled !== true` as 404, so both endpoints agree on what a live widget is.

## Why the copies of the names
The token endpoint's role reads route items only (ADR-0003: nothing under `TENANT#`). The names are only for the greeting; the worker still gets the real
agent config from the resolver. If the copies are missing the endpoint falls back to a nameless greeting and the agent name "Ava".
