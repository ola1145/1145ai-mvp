# C4-2: what the webchat token Lambda needs in `ChannelsStack`

From: C4 (customer web chat token). To: C1 (owner of `infra/cdk/lib/channels-stack.ts`); `data-stack.ts` part goes to C0.

## Today
`ChannelsStack` creates `WebchatToken` with the shared `env` (`QUEUE_URL`, `TABLE_NAME`, `EVENT_BUS_NAME`) and `grantRouteRead`. The handler is now real and needs more.
Until these land the Lambda answers 503 (`missing env RUNTIME_SECRET_ID`), which is the safe failure.

## Requested changes in `channels-stack.ts`
1. Env `RUNTIME_SECRET_ID = '1145/<stage>/runtime'` on the `WebchatToken` function (same secret name the router uses). It holds `LIVEKIT_URL`,
   `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` (see `docs/API_KEYS.md`). The helper `fn()` needs an optional extra-env argument for this.
2. Read access to that secret: `sm.Secret.fromSecretNameV2(this, 'WebchatRuntimeSecret', '1145/' + stage + '/runtime').grantRead(webchatToken)`.
3. Rate-limit counters (item shape in C4-1): 
   ```ts
   webchatToken.addToRolePolicy(new iam.PolicyStatement({
     actions: ['dynamodb:UpdateItem'],
     resources: [props.data.table.tableArn],
     conditions: { 'ForAllValues:StringLike': { 'dynamodb:LeadingKeys': ['RATELIMIT#*'] } },
   }));
   props.data.table.encryptionKey?.grantEncryptDecrypt(webchatToken);   // writes need GenerateDataKey; grantRouteRead only decrypts
   ```
   If this is not granted the handler logs a warning per request and keeps limiting per container only. It does not fail the request.
4. Route methods for `/v1/webchat/token`: `[POST, OPTIONS]` to the same integration. The handler answers the CORS preflight itself.
   (An `HttpApi` `corsPreflight` block would also work, but it applies to every route on `hooks`.)
5. Backstop, optional: stage-level throttling on the `hooks` HttpApi (for example burst 50, rate 25 per second) so a flood is cut before it
   reaches Lambda. The per-IP and per-key limits in the handler are the real controls; this only caps cost.
6. Lambda timeout 5 s is fine (one DynamoDB read, two counter writes, one cached secret read, local signing).

## Not needed
No LiveKit network call and no `RoomService` permission: the token carries the room config, and the room only exists once the visitor connects.
