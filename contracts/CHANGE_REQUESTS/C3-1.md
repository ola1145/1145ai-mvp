# C3-1: document the owner-chat responses, and two things the Hooks API needs before a browser can use it

**From:** C3 (owner web chat API) · **To:** owner of `contracts/openapi/channels.yaml`, and owner of `infra/cdk/lib/channels-stack.ts` (C1 / P2)

`services/channels/src/owner-chat.ts` is built and tested against the shapes below. The contract file only says `'202': Accepted`, so the
owner app has nothing to code against for the other outcomes.

## 1. `contracts/openapi/channels.yaml`: `postOwnerChatMessage` responses (additive)
```yaml
      responses:
        '202':
          description: Queued for the router. The reply arrives on AppSync Events /owners/<sub>/chat. Safe to repeat with the same clientMessageId.
          content: { application/json: { schema: { type: object, required: [accepted, clientMessageId], properties: { accepted: { type: boolean, const: true }, clientMessageId: { type: string } } }, examples: { ok: { value: { accepted: true, clientMessageId: c_01J9ZS } } } } }
        '400': { description: 'Bad request. code is one of bad_request, empty_text, text_too_long, invalid_client_message_id, invalid_referral_code.', content: { application/json: { schema: { $ref: '#/components/schemas/OwnerChatError' } } } }
        '401': { description: 'No usable Cognito sub in the token (code unauthorized). The app should sign the owner in again.', content: { application/json: { schema: { $ref: '#/components/schemas/OwnerChatError' } } } }
        '413': { description: 'Body larger than 96 KB (code too_large).', content: { application/json: { schema: { $ref: '#/components/schemas/OwnerChatError' } } } }
        '503': { description: 'Could not reach the queue in time (code unavailable). Has a Retry-After header. Retry with the same clientMessageId; it is deduplicated.', content: { application/json: { schema: { $ref: '#/components/schemas/OwnerChatError' } } } }
```
and under `components.schemas`:
```yaml
    OwnerChatError:
      type: object
      required: [code, messageForOwner]
      properties:
        code: { type: string, enum: [unauthorized, bad_request, empty_text, text_too_long, invalid_client_message_id, invalid_referral_code, too_large, unavailable, internal] }
        messageForOwner: { type: string, description: 'A line the app can show as is (follows 1145-conversation-style).' }
```
Also in the request description: `clientMessageId` is 1 to 64 visible characters with no whitespace or control characters; `referralCode: null` is
treated as absent; the sender is always the Cognito `sub` of the token and no other field in the body is read for identity.
The app should send the ID token: its `given_name` (or first word of `name`) claim is passed to the agent as the owner's first name.

## 2. `infra/cdk/lib/channels-stack.ts`: CORS on the `Hooks` HttpApi
The owner app (`https://app.1145.ai`) calls `{hooks}/v1/owner-chat/messages` from the browser with an `Authorization` header, so the
browser sends a preflight. The `Hooks` HttpApi has no `corsPreflight`, so every web chat request would be blocked. Same pattern as
`controlplane-stack.ts` (`consoleOrigins`):
```ts
corsPreflight: { allowOrigins: ownerAppOrigins, allowMethods: [apigw.CorsHttpMethod.POST], allowHeaders: ['authorization', 'content-type'], maxAge: Duration.hours(1) }
```
with `ownerAppOrigins` read from a context value (for example `ownerAppOrigins`), not `*`. `/v1/webchat/token` is also called from
customers' sites, so that one needs its own origin decision (C4).

## 3. Throttling (threat model SEC-25)
Each accepted owner message becomes one paid agent run. Please set stage default route throttling on `Hooks` (a floor of a few requests per second
per route is plenty for owners typing). A per-owner cap needs state, which this Lambda deliberately does not have (it only has `sqs:SendMessage`),
so it belongs in the router (C1): count messages per `webchat` sub per minute and answer with a short "give me a minute" line instead of invoking the agent.
