# P3-1: tests/e2e/package.json has no owner (P8-1, Q1-1)

**From:** P3 · **To:** the orchestrator (`orchestration/issues.ts`) · **Contract change:** no · **Blocking:** no

## What
`tests/e2e/package.json` (and its `package-lock.json`) belongs to no issue: P8 owns `tests/e2e/harness/**`,
`tests/e2e/scenarios/**` and `e2e.yml`, Q1 owns `tests/e2e/isolation/**`, and P3's owns list has the root `package.json`
only. P8-1 asks P3 for the file, but adding it from the P3 branch fails the `ownership` check, and now that the check runs
from the base commit (SEC-01) a PR cannot widen its own ownership to get around that.

## Proposed change
1. In `orchestration/issues.ts` add `'tests/e2e/package.json', 'tests/e2e/package-lock.json'` to the **P3** owns list
   (P3 owns every dependency list and lockfile).
2. Then add the staged file `contracts/CHANGE_REQUESTS/P3-1.tests-e2e-package.json.txt` as `tests/e2e/package.json` and run
   `cd tests/e2e && npm install --package-lock-only --ignore-scripts` to create the lockfile.

The staged file merges P8-1 (`test`, `gate:live`) and Q1-1 (`isolation` = `vitest run --root isolation`, plus `vitest`
`^2.1.0` as the only devDependency). P8's `test` script is the same `node --test` command `e2e.yml` runs today.

## Why it is not blocking
`e2e.yml` (P8 branch) runs the isolation suite from the repo root with `pnpm vitest run --root tests/e2e/isolation`, so the
workflow does not need this file. Only the briefs' run commands (`cd tests/e2e && npm test` and `npm run isolation`) do.
