# A4-1: evals CI job, typecheck coverage, Makefile target

Requested by: A4 (eval runner, LLM judge, conversation-style gate)
Owner of the files: P3 (CI and repo plumbing)

## What and why
The brief's acceptance is "evals job runs in CI on prompt/template changes". A4 only owns `evals/**` and
`packages/conversation-style/**`, so the workflow, root tsconfig and Makefile changes need another lane.
`pnpm vitest run` already picks up `evals/**/test/**/*.test.ts` through the root `vitest.config.ts`, so the unit
tests and the full scenario suite (against the fakes) run in the existing `typescript` job. What is missing is a
path-triggered job and typecheck coverage.

## Proposed changes

1. `.github/workflows/ci.yml`: add a job that runs when prompts, templates, the style package or evals change.

```yaml
  evals:
    runs-on: ubuntu-latest
    if: >-
      github.event_name == 'pull_request'
    steps:
      - uses: actions/checkout@v6
      - uses: dorny/paths-filter@v3
        id: changed
        with:
          filters: |
            evals:
              - 'evals/**'
              - 'packages/conversation-style/**'
              - 'agents/**/system_prompt.md'
              - 'agents/**/prompts*'
              - 'engines/livekit-agent/src/prompts.py'
              - 'services/**/templates/**'
      - if: steps.changed.outputs.evals == 'true'
        uses: pnpm/action-setup@v4
      - if: steps.changed.outputs.evals == 'true'
        uses: actions/setup-node@v4
        with: { node-version: 22, cache: pnpm }
      - if: steps.changed.outputs.evals == 'true'
        run: pnpm install --frozen-lockfile
      - if: steps.changed.outputs.evals == 'true'
        run: pnpm exec tsx evals/src/cli.ts --runs 2
```

   If `dorny/paths-filter` is not on the allowed-actions list, use `on.pull_request.paths` in a separate workflow file instead.
   Add the job name to the required checks (or to `main-green`'s `needs`).

2. `tsconfig.json`: add `"evals/**/*.ts"` to `include` so `make typecheck` covers the runner (A4 checked it clean with a temporary config).

3. `Makefile`: add `evals: pnpm exec tsx evals/src/cli.ts --runs 5` as a target, and `.PHONY` entry.

4. Live wiring, later: a nightly job that runs the same CLI with a Bedrock-backed `LlmJudge` and a live adapter for the
   LiveKit text session and the AgentCore chat agents. Credentials and the paid calls belong to that job, not to PR CI.

5. `scripts/ci/check-style.ts`: optionally also run `checkReply` over every `fake` reply and greeting in
   `evals/scenarios/*.yaml` (the vitest suite already does, so this is only for a faster failure message).
