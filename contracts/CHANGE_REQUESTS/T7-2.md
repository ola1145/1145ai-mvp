# T7-2: S3 Vectors + Bedrock wiring for tool-api (follow-up to T0-1)

**From:** T7. **Needs:** P3 (dependencies), contracts owner (keys.md), then T7 or T0 to finish the wiring.

## Done in T7 (no new dependencies)
- `ddb-repo.ts`: `getHandoffWindow()` reads `PROFILE.handoffWindow` (same shape as `HOURS`). `ddbRepoFor` returns it
  as `TenantRepo & { getHandoffWindow() }`, so it works whether or not `TenantRepo` has the optional method yet (T0).
- `deps.ts`: `s3VectorsKnowledge(ports)` implements T0's `KnowledgeIndex` over two injected functions
  (`embed`, `queryVectors`). It passes `q.filter` through untouched, and drops any hit whose `tenantId` differs from
  `q.tenantId` or that has no text. `prodDeps(knowledge?)` sets `deps.knowledge` when ports are supplied.
  Without ports, handlers keep using `searchVerifiedFacts`.

## Note on tenant ids
`ddb-repo.ts` now rejects tenant ids outside `[A-Za-z0-9_-]{1,64}` before AssumeRole (the id becomes an IAM session
tag and a key prefix). If the provisioning lane generates ids with other characters, tell T7.
