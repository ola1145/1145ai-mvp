# T0-1: wire S3 Vectors and the handoff window into the production deps/repo

**From:** T0 (tool-api core). **Needs:** owner of `services/tool-api/src/deps.ts` and `services/tool-api/src/lib/ddb-repo.ts`, plus P3 for the dependency.

## What T0 shipped (in owned files)
- `TenantRepo.getHandoffWindow?(): Promise<BusinessHours | undefined>` (optional). `requestHandoff` transfers only when the instant is inside this window, else inside business hours, else (nothing configured) always.
- `ToolDeps.knowledge?: KnowledgeIndex` plus `knowledgeFilter(tenantId, verifiedOnly)` in `lib/repo.ts`. `searchKnowledge` uses it when present, re-checks tenant and verified on every hit, and falls back to `searchVerifiedFacts` when absent or failing.

## Requested changes
1. `ddb-repo.ts`: implement `getHandoffWindow()` reading `PROFILE.handoffWindow` (`{ timezone, weekly: [{day, open, close}], closedDates? }`, same shape as `HOURS`). Add the attribute to `contracts/dynamodb/keys.md` (profile row).
2. `deps.ts`: set `knowledge` to an S3 Vectors implementation: `QueryVectorsCommand({ vectorBucketName, indexName, queryVector: <Bedrock Titan embedding of q.text>, topK: q.topK, filter: q.filter, returnMetadata: true })`, mapping metadata `{ text, source, verified, tenantId }` to `KnowledgeHit`. Pass `q.filter` as-is; never build the tenant filter from anything else.
3. P3: add `@aws-sdk/client-s3vectors` and `@aws-sdk/client-bedrock-runtime` to `services/tool-api/package.json` (declared dependencies are frozen for lane agents), plus IAM `s3vectors:QueryVectors` and `bedrock:InvokeModel` on the tool-api Lambda role.
4. Ingest side (knowledge lane): each vector must carry filterable metadata `tenantId` (string) and `verified` (boolean) so the filter applies; unverified or instruction-flagged facts are indexed with `verified: false`.
