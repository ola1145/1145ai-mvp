# Q1-3: dev fixtures and an e2e IAM role for the isolation run

**From:** Q1 · **To:** infra owner (data/IAM stack) and the dev-deploy owner

## What
1. Two dedicated throwaway dev tenants, A and B, seeded with: a confirmed booking and a service for B, a verified
   knowledge fact for B, a confirmed booking for A, and a distinctive string (for example a customer first name) that
   exists only in B. Their ids, B's booking and service ids and that string feed the `ISOLATION_*` variables.
2. An IAM role for the e2e job that may call `sts:AssumeRole` and `sts:TagSession` on the tenant data role
   (`TenantDataRole`), and nothing else.
3. Tool tokens for A and B with the owner principal, and a Cognito owner login for A (and optionally B), exposed to the
   e2e job as secrets.
4. The AppSync Events HTTP host (`1145-live`) published as a deploy output.

## Why
The isolation suite targets the real dev stack and reads all of this from environment variables. Without fixtures the
controls fail by design (an unseeded B would otherwise make every "no B data" check pass vacuously).
