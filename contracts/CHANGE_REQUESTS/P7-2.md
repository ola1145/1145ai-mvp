# P7-2: emit the call and tool metrics the alarms read (owners: tool-api T-lane, voice worker, post-call G3)

**What.** Publish these as CloudWatch Embedded Metric Format lines (a JSON log line with an `_aws` block; no SDK call,
no extra IAM) in namespace `Ai1145`:

| Metric | Unit | Dimensions | Emitted by | When |
| --- | --- | --- | --- | --- |
| `CallStarted` | Count | none | `engines/livekit-agent` | job accepted |
| `CallCompleted` | Count | none | `engines/livekit-agent` | call ended normally |
| `CallFailed` | Count | none | `engines/livekit-agent` | call ended on an error (worker crash, STT/TTS/LLM failure, tool failure that dropped the call) |
| `ToolLatencyMs` | Milliseconds | `Route` = handler file name, e.g. `check-availability` | `services/tool-api` handlers | every request, success or failure, measured inside the handler |
| `CallMinutes` | None (minutes) | `TenantId` | `services/post-call` | once per call, from the call duration |

Constants live in `infra/cdk/lib/observability-stack.ts` (`METRICS`, `VOICE_TOOL_ROUTES`). `TenantId` as a metric
dimension is for the ops dashboard only; it never feeds billing.

**Why.** The failed-call alarm, the per-route p95 alarms and several dashboard widgets read these. Until they exist the
alarms stay quiet (missing data is treated as fine) and the widgets are empty.

**Also asked.** Put the call id (room name / conversation id) in every log line as a field, so the saved
`trace-one-call` Logs Insights query in the observability stack finds the whole call (W2-23).
