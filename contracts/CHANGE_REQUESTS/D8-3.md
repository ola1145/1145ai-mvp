# D8-3: call result lookup and a Lambda-side VoiceEngine factory for the smoke call

**From:** D8 · **To:** G3 (post-call), E6 (livekit-adapter), E7 (elevenlabs-adapter), D5 (engine construction), E1 (Telnyx outbound profile)
**Not blocking:** `smoke-call` is built against two small interfaces (`outcomes.waitForEnd`, `engineFor`) with fakes.
Its Lambda entry fails loudly on the missing factory instead of guessing.

## 1. G3: store the call result where the smoke call can read it (new, small)
The smoke call succeeds only on `call.ended` with `durationSec > 10` and no error end reason, and the Lambda has no way
to see EventBridge events. On every `call.ended` (both engines, with or without a transcript), post-call should also write:

    PutItem  PK = TENANT#<tid>   SK = CALLEND#<callId>
             durationSec, endReason, endedAt (ISO), ttl (now + 7 days)

`<tid>` is the envelope's `tenantId`; `<callId>` is `data.callId`. The write is idempotent (same item on replay), is
independent of analysis, and should happen first so the owner's smoke call is not held up by the Bedrock analysis.
`smoke-call` polls this item every 2 s with a consistent read, for at most 90 s per call (less if the Lambda has less
time left), and treats "nothing by then" as a missed call. Post-call needs `dynamodb:PutItem` on `TENANT#*` for this,
which it will already have for its `POSTCALL#` marker and usage writes.

## 2. E6 and E7: the id returned by `placeSmokeTestCall` must be the id `call.ended` carries
`smoke-call` looks up `CALLEND#<callId>` with the `callId` that `placeSmokeTestCall` returned.
- ElevenLabs (E7): returns `conversation_id`, and `normalizeCallEvent` uses `data.conversation_id`. They match.
- LiveKit (E6): `dialOut` returns a string, while the worker publishes `call.ended` with `sip.callID` when the SIP
  participant has one and the room name otherwise (`worker.py`: `call_id = info.call_id or ctx.room.name`). Please make
  `dialOut` return the same value the worker will use for that room, and note in `placeSmokeTestCall` which one it is.
  If the ids can differ, tell D8 and the lookup can switch to the room name (`smoke-<tenantId>-<ts>`).
- Both engines: the call from the tenant's own number to the owner is an ordinary call from the worker's point of view;
  the greeting the owner hears is the normal front-desk greeting with the AI and recording disclosure.

## 3. D5 / whoever owns engine construction: a `VoiceEngine` factory usable inside a Lambda
`render-agent.ts` already notes that "bind-engine owns engine construction", and `smoke-call.ts` needs the same thing:

    engineFor(engine: EngineId): Pick<VoiceEngine, 'placeSmokeTestCall'>      // render-agent also needs updateTenantAgent, syncKnowledge

- LiveKit: `LiveKitTelnyxEngine` with real deps (outbound trunk id, LiveKit API key and secret from Secrets Manager,
  `SipClient.createSipParticipant` plus `AgentDispatchClient`). The provisioning package would need the adapter packages
  as workspace dependencies; that is a P3 change to `services/provisioning/package.json`, not something D8 does.
- ElevenLabs: `ElevenAgentsEngine` with the API key, webhook secret and SIP trunk config.
Suggested home: `services/provisioning/src/lib/engines.ts`, exporting `engineFor`, which both RenderAgent and SmokeCall
inject. Once it exists, replace the throwing `engineFor` in `smoke-call.ts`'s `handler` (one line).

## 4. E1: restrict the outbound path at the carrier too (SEC-19, AB-4, AB-5)
`smoke-call` allow-lists the destination in code (NANP only, no premium, toll-free, non-geographic or non-US/CA
country codes, never the tenant's own line) and caps attempts at two per onboarding. The Telnyx outbound voice profile
used by the LiveKit outbound trunk should enforce the same limits (US and Canada only, premium and international
blocked, a daily spend or minute cap) so the code check is not the only control.
