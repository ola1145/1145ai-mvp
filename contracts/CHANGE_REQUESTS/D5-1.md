# D5-1: execution input contract and ORDER# key (from D5, number search/order/bind)

## What
1. D1 (`services/provisioning/src/api/provisioning.ts`) must start the state machine with an input that contains, at the top level:
   - `onboardingId` (also the execution name)
   - `tenantId` (server-side value, format `t_[a-z0-9]{8,40}`; never from model output)
   - `area`: `{ areaCode?: string, state?: string }` taken from the saved basics (3-digit area code, 2-letter state)
   The D5 steps read these from the workflow state. A missing or malformed `area` makes SearchNumber fail with `NoNumberAvailable`.
2. `contracts/dynamodb/keys.md` and `packages/shared/src/keys.ts`: add the purchase-idempotency item D5 writes.

## Why
SearchNumber/OrderNumber/BindEngine run as Step Functions tasks and cannot ask anyone for these values. `ORDER#` is the
"never bought twice" record (conditional put, first writer wins).

## Proposed change
keys.md row:

| Number order | `TENANT#<tid>` | `ORDER#<onboardingId>` | number, orderId, createdAt; conditional put `attribute_not_exists(PK)` |

keys.ts: `orderSk: (onboardingId: string) => \`ORDER#${seg(onboardingId, 'onboardingId')}\``

D5 currently builds the key inline (`ORDER#${onboardingId}`) so nothing is blocked; swap to the builder once it exists.

## Also for P2/P4 (informational)
`ProvisioningStack` now creates a Secrets Manager secret `TelnyxSecret` with JSON keys `TELNYX_API_KEY` and
`TELNYX_CONNECTION_ID`. `scripts/secrets/push.sh` (not D5-owned) should write those two keys into it.
