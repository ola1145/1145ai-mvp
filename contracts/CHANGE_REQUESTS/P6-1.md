# P6-1: owner-chat reply event shape, `ops` Cognito group, tokens carrying `custom:tenant_id`

From: P6 (AppSync Events publisher). To: C0/contracts owner (events), C1/C3 (owner chat), P5 (auth).

## 1. Owner chat replies on the event bus (contracts/events/events.schema.json, C1/C3)
The publisher routes `/owners/<sub>/chat` from a `conversation.message` event whose `data` is:

    { "audience": "owner_chat", "ownerSub": "<Cognito sub, UUID>", "text": "<reply>" }

- `ownerSub` must be the Cognito `sub` from the verified JWT (never model output). Non-UUID values are dropped.
- Such events are never sent to `/tenants/<tid>/live`. `audience` and `ownerSub` are stripped from the payload.
- Proposed `$defs` addition: `conversation.message` with optional `audience` (enum `["owner_chat"]`), `ownerSub`, `text`.
- Producer: the router (C1/C3), source `1145.channels`, put on the 1145 bus. The publisher only accepts `source` `1145.*`.

## 2. `ops` Cognito group (infra/cdk/lib/auth-stack.ts, P5)
`/ops/fleet` is allowed only when the token's `cognito:groups` contains `ops`. Please add a `CfnUserPoolGroup` named `ops`.
Until it exists nobody can subscribe to `/ops/fleet` (safe default).

## 3. Tokens must carry `custom:tenant_id` (P5 pre-token trigger)
`/tenants/<tid>/live` compares the path to the token claim `custom:tenant_id`. If the client sends the access token,
the pre-token trigger must add the claim there too (ID tokens include custom attributes by default).

## 4. Event bus rule
P6 added `tenant.state_changed` to the live rule so `/ops/fleet` receives fleet state changes. No action needed.
