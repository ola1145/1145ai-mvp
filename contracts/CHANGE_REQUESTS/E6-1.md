## Worker events (informational)
`verifyWorkerEvent` accepts the exact envelope `engines/livekit-agent/src/frontdesk/events.py` builds, with
`Authorization: Bearer <call token>` (the resolver's call-scoped token, `prn: customer-agent`, `cid` = call id) or a `system` token.
The tenant is always the token's `tid`; a body that names another tenant or a different call is rejected. Today the worker publishes
straight to EventBridge, so nothing posts these over HTTP yet. If the team wants the verified HTTP path (for example to make
`normalizeCallEvent` the single entry for `call.ended` on both engines), the worker's `CallEvents` needs a sender that adds the
header, and an endpoint needs to call `engine.normalizeCallEvent`. Not required for the MVP flow.
